The HiveWard CLI is the `hiveward` command-line interface for scripting a running HiveWard editor from any shell. Use it to create and inspect worktrees, drive agent terminals, open files and diffs, automate the built-in browser, run scheduled automations, share HTML/Markdown artifacts, and control HiveWard-native tools from scripts or AI agents.

It ships with the desktop app; register it under [Settings → General → HiveWard CLI](/docs/settings). On Linux the command is `hiveward-ide`, because GNOME HiveWard's screen reader already owns `/usr/bin/hiveward` — see [Install → Linux](/docs/install#linux).

Agents can install the matching HiveWard CLI skill with:

```bash
npx skills add https://github.com/Chaunyzhang/HiveWard --skill hiveward-cli
# headless / no Settings UI:
hiveward skills install --skill hiveward-cli
```

See [Skills registry & MCP](/docs/cli/skills) for every installable HiveWard skill, including `hiveward skills install` / `hiveward skills update`.

## Install & verify

```
command -v hiveward
hiveward status --json
```

## Worktree commands

```
hiveward worktree ps --json
hiveward worktree create --repo id:<repoId> --name my-task --issue 123 --json
hiveward worktree create --repo id:<repoId> --name review-pr-123 --pr 123 --json
hiveward worktree current --json
hiveward worktree set --worktree active --comment "reproduced bug" --json
hiveward worktree set --worktree active --gitlab-issue 42 --gitlab-mr 77 --json
hiveward worktree set --worktree active --pr null --json
hiveward worktree rm --worktree id:<id> --force --json
```

For selectors, setup flags, parent/child worktrees, and the broader command map, see [HiveWard CLI reference](/docs/cli/reference).

## Terminal commands

```
hiveward terminal list --json
hiveward terminal read --json
hiveward terminal send --text "continue" --enter --json
hiveward terminal wait --for tui-idle --timeout-ms 30000 --json
hiveward terminal create --worktree path:/projects/app --command "npm test" --json
hiveward terminal split --direction vertical --command "npm run dev" --json
```

For tracked multi-agent work, use [Orchestration](/docs/cli/orchestration) instead of plain terminal prompts.

## File commands

Open files and diffs as tabs in their HiveWard worktree from a shell. They open without changing what you are looking at; add `--focus` to be brought to the file:

```
hiveward file open src/App.tsx
hiveward file diff src/App.tsx --staged
hiveward file open-changed --mode both
```

Use `--worktree <selector>` when the shell's current directory is not inside the target worktree.

## Browser profiles

Browser profiles isolate tab session state, so a script or agent can test with different cookies, local storage, and logged-in identities. The CLI exposes profile commands under `hiveward tab profile`; start with `hiveward tab profile list --json`, then use `create`, `set`, `clone`, or `use-default` as needed.

## Scheduled automations

Use `hiveward automations` to create, inspect, run, and remove scheduled HiveWard tasks from a shell. Start with [Scheduled automations](/docs/cli/automations) when you want a recurring prompt to run against a repo or an existing worktree.

## Artifacts

Share HTML or Markdown as public view links through the signed-in HiveWard account (`hiveward artifacts share|update|list|delete`). Publishing is **opt-in** under Settings → Artifacts. Command details: [CLI reference → Artifacts](/docs/cli/reference#artifacts).

## Browser automation

The CLI also drives the built-in browser with a snapshot-interact-re-snapshot loop:

```
hiveward goto --url https://example.com --json
hiveward snapshot --json     # returns refs like @e1, @e3
hiveward click --element @e3 --json
hiveward fill --element @e1 --value "user@example.com" --json
hiveward screenshot --json
```

For responsive browser checks, switch the active tab to a named device profile:

```
hiveward set device --name "iPhone 12" --json
hiveward screenshot --json
```

## Mobile emulator

The CLI can also drive an iOS Simulator through HiveWard's mobile emulator bridge. It is scoped to the active worktree, so agents and scripts can attach a simulator, list the worktree's attached devices with `hiveward emulator list`, tap normalized coordinates, type text, send gestures, rotate the device, and shut it down without leaving HiveWard.

```
hiveward emulator list --json
hiveward emulator attach "<device-name-or-udid>" --json
hiveward emulator tap 0.5 0.7 --json
hiveward emulator type "hello" --json
hiveward emulator gesture '[{"type":"begin","x":0.5,"y":0.8},{"type":"move","x":0.5,"y":0.4},{"type":"end","x":0.5,"y":0.2}]' --json
hiveward emulator rotate landscape_left --json
hiveward emulator kill --json
```

Use `--worktree <selector>`, `--device <udid-or-name>`, or `--emulator <id>` when a script needs an explicit target.
